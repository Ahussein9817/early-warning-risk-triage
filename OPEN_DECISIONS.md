# Open Decisions, read before directing the agent in Claude Code

**Status as of 2026-08-23:** all four decisions are resolved (embedding model, deployment target, build mode, hand-labeled sample size), and the dashboard is live: https://early-warning-risk-triage.streamlit.app. Nothing outstanding in this file.

1. **Embedding model (Requirements section), RESOLVED.** `sentence-transformers/all-MiniLM-L6-v2` (384-dim, ~80MB), chosen for fast CPU inference and small footprint over `all-mpnet-base-v2` (slower, larger) and `BAAI/bge-small-en-v1.5` (needs a query-instruction prefix). Confirmed finalized and documented in both `BUILD_INSTRUCTIONS.md` Requirements and `README.md` Methodology → Text embeddings, not left unstated.

2. **Streamlit deployment target, RESOLVED, then REVISED 2026-08-23.** Originally chosen: HuggingFace Spaces, GitHub-synced. Reversed after discovering HF deprecated the free-tier Streamlit SDK: Streamlit apps now require the Docker SDK, and creating a Docker (or Gradio) Space now requires a paid PRO subscription ($9/month) for personal accounts, a real platform change made after the original decision, not something known at the time. **Revised target: Streamlit Community Cloud** (one of the three original options in this file's first draft), free, connects directly to the GitHub repo, no payment required.
   - **RESOLVED 2026-08-23: deployed and live.** https://early-warning-risk-triage.streamlit.app. Deployment hit a real snag worth recording: Streamlit Community Cloud's default Python version (3.14) lacks prebuilt wheels for pandas/PyYAML, forcing slow source builds that looked like a stalled/broken deploy; a first attempted fix (`--extra-index-url` for a CPU-only torch wheel in `requirements.txt`) actively broke `uv`'s resolver and was reverted. Actual fix: delete and redeploy with Python pinned to 3.12 via the "Advanced settings" dialog at creation time (`runtime.txt` is currently unreliable/ignored on this platform, a known active issue, not a fix to rely on). `project_description.md`'s "deployed Streamlit dashboard" deliverable is now satisfied.


3. **Hand-labeled evaluation sample size, RESOLVED (emerged during Section 6, not in the original three).** Spec called for 100-200 rows. A 150-row template was generated (`src/sample_for_labeling.py`, seeded random sample from the model's test split, excluding `company_response`/`timely`/the proxy label to keep the labeler's judgment independent). 106 of the 150 were actually hand-labeled, within the 100-200 range, so usable as-is; the remaining 44 were never filled in and evaluation proceeded on 106. A follow-up consistency-recheck pass (19 rows, 18 corrected) fixed a labeling inconsistency between `"Debt is not yours"` and `"Debt was result of identity theft"` sub_issues, documented in `BUILD_INSTRUCTIONS.md` Inputs and `README.md` Methodology, not silently corrected.

## Reminders from the source material, for when you're actually running the cycle in Claude Code

- Only interact with the agent through the spec, don't give it verbal patches that don't make it back into `BUILD_INSTRUCTIONS.md`. If a fix works, write it into the spec so the next run reproduces it.
- "The agent wrote it, so it's right" is the first trap. Spot-check baseline vs. fused predictions against the actual narrative text by hand before trusting `comparison_report.md`.
- "It worked on the sample" is the third trap. CFPB narratives are messy, test the empty-narrative path and a malformed-record path explicitly, not just the happy path.
